# Agent File Sending — All Channels

**Status:** Draft — awaiting Reviewer approval  
**Work Item:** item-e2t9tummvQPqLoYmmPFBe  
**Date:** 2026-04-13

## Overview

Enable agents to send files (images, documents, audio, video) to any connected channel via the `send_message` MCP tool. Today, agents can only send text. This change adds an optional `file` parameter to `send_message`, extends the IPC message JSON with a `file` object, and teaches each channel adapter to upload the file via the platform's native API.

The file must already exist on the container filesystem (e.g., generated by the agent, or present in a mounted volume). The agent references it by absolute container path.

## 1. MCP Tool Changes (`ipc-mcp-stdio.ts`)

### Updated `send_message` parameters

```typescript
server.tool(
  'send_message',
  'Send a message (with optional file attachment) to the user or group.',
  {
    text: z.string().describe('The message text to send. Can be empty string when sending a file-only message.'),
    sender: z.string().optional().describe('Your role/identity name (e.g. "Researcher").'),
    filePath: z.string().optional().describe(
      'Absolute container path to the file to send (e.g. "/workspace/group/output/report.pdf"). The file must exist.'
    ),
    fileName: z.string().optional().describe(
      'Display name for the file (e.g. "quarterly-report.pdf"). Defaults to the basename of filePath.'
    ),
    mimeType: z.string().optional().describe(
      'MIME type (e.g. "image/png", "application/pdf"). Auto-detected from extension if omitted.'
    ),
  },
  async (args) => { /* ... */ },
);
```

### Validation rules

| Rule | Error message |
|------|---------------|
| `filePath` provided but file does not exist | `File not found: {filePath}` |
| `filePath` does not start with `/workspace/` | `File must be under /workspace/` (security: no container escape) |
| File size exceeds 50 MB | `File too large: {size}MB (max 50MB)` |
| `fileName` without `filePath` | `fileName requires filePath` |
| `mimeType` without `filePath` | `mimeType requires filePath` |
| Both `text` and `filePath` are empty/missing | `Either text or filePath is required` |

### MIME type detection

When `mimeType` is omitted, derive it from the file extension:

| Extension | MIME Type |
|-----------|-----------|
| `.png` | `image/png` |
| `.jpg`, `.jpeg` | `image/jpeg` |
| `.gif` | `image/gif` |
| `.webp` | `image/webp` |
| `.pdf` | `application/pdf` |
| `.mp4` | `video/mp4` |
| `.mp3` | `audio/mpeg` |
| `.ogg` | `audio/ogg` |
| `.wav` | `audio/wav` |
| `.doc`, `.docx` | `application/msword` / `application/vnd.openxmlformats-officedocument.wordprocessingml.document` |
| `.xls`, `.xlsx` | `application/vnd.ms-excel` / `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| (unknown) | `application/octet-stream` |

## 2. IPC Message Format

### Current schema (text only)

```json
{
  "type": "message",
  "chatJid": "tg:-1001234567890",
  "text": "Here is the report",
  "sender": "Researcher",
  "groupFolder": "telegram_dev-team",
  "timestamp": "2026-04-13T10:00:00.000Z"
}
```

### Updated schema (with optional file)

```json
{
  "type": "message",
  "chatJid": "tg:-1001234567890",
  "text": "Here is the report",
  "sender": "Researcher",
  "groupFolder": "telegram_dev-team",
  "timestamp": "2026-04-13T10:00:00.000Z",
  "file": {
    "path": "/workspace/group/output/report.pdf",
    "name": "quarterly-report.pdf",
    "mimeType": "application/pdf",
    "size": 1048576
  }
}
```

The `file` field is optional. When absent, behavior is identical to today (text-only message). When present:

- `file.path` — absolute path inside the container (validated to exist at write time)
- `file.name` — display name for the recipient
- `file.mimeType` — resolved MIME type
- `file.size` — file size in bytes (set at write time for host-side limit checks)

### Host-side path resolution

The container path `/workspace/group/output/report.pdf` maps to the host via the group's volume mount. The IPC watcher already knows the group's host directory from `registeredGroups[jid].folder`. The host resolves:

```
{dataDir}/groups/{group.folder}/output/report.pdf
```

The IPC watcher must validate that the resolved host path:
1. Exists on disk
2. Falls within the group's directory (no path traversal via `../`)
3. Is a regular file (not a directory or symlink to outside)

## 3. Type Definitions

### New types (shared or in `ipc-mcp-stdio.ts`)

```typescript
interface IpcFileAttachment {
  path: string;      // Container-absolute path
  name: string;      // Display filename
  mimeType: string;  // Resolved MIME type
  size: number;      // Bytes
}

interface IpcOutboundMessage {
  type: 'message';
  chatJid: string;
  text: string;
  sender?: string;
  groupFolder: string;
  timestamp: string;
  file?: IpcFileAttachment;
}
```

### Updated `Channel` interface

```typescript
interface Channel {
  name: string;
  connect(): Promise<void>;
  sendMessage(jid: string, text: string): Promise<void>;
  sendFile?(jid: string, file: HostFileAttachment, caption?: string): Promise<void>;
  isConnected(): boolean;
  ownsJid(jid: string): boolean;
  disconnect(): Promise<void>;
  setTyping?(jid: string, isTyping: boolean): Promise<void>;
  syncGroups?(force: boolean): Promise<void>;
}

interface HostFileAttachment {
  hostPath: string;  // Resolved absolute path on host filesystem
  name: string;      // Display filename
  mimeType: string;  // MIME type
  size: number;      // Bytes
}
```

`sendFile` is optional on `Channel`. If a channel doesn't implement it and a file message arrives, the IPC watcher sends the text portion only and logs a warning.

### Updated `ChannelDriver` (public API)

```typescript
interface ChannelDriver {
  connect(): Promise<void>;
  disconnect(): Promise<void>;
  sendMessage(jid: string, text: string): Promise<void>;
  sendFile?(jid: string, file: HostFileAttachment, caption?: string): Promise<void>;
  isConnected(): boolean;
  ownsJid(jid: string): boolean;
  setTyping?(jid: string, isTyping: boolean): Promise<void>;
  syncGroups?(force: boolean): Promise<void>;
}
```

## 4. IPC Watcher Changes (`ipc.ts`)

The message processing block in `processIpcFiles` currently calls `deps.sendMessage(data.chatJid, data.text)`. Updated logic:

```
if data.file exists:
  1. Resolve host path: join(dataDir, 'groups', sourceGroup, relative(data.file.path))
  2. Validate host path is under group directory (no traversal)
  3. Validate file exists and is a regular file
  4. Find channel for data.chatJid
  5. If channel.sendFile exists:
       call channel.sendFile(jid, hostFile, data.text || undefined)
     Else:
       log warning "Channel {name} does not support file sending"
       if data.text: call deps.sendMessage(jid, data.text)
else:
  call deps.sendMessage(jid, data.text)   // existing behavior
```

The `IpcDeps` interface gains:

```typescript
interface IpcDeps {
  // ... existing fields ...
  sendFile: (jid: string, file: HostFileAttachment, caption?: string) => Promise<void>;
}
```

Or alternatively, pass the channel array so IPC can call `sendFile` directly. This avoids threading yet another function through deps. Decision: **add `sendFile` to `IpcDeps`** for consistency with the existing `sendMessage` pattern.

## 5. Per-Channel Adapter Implementation

### 5.1 Telegram (`channels/telegram.ts`)

**API:** `bot.api.sendDocument()`, `bot.api.sendPhoto()`, `bot.api.sendVideo()`, `bot.api.sendAudio()`, `bot.api.sendVoice()`

**Method selection by MIME type:**

| MIME prefix | Grammy method | Notes |
|-------------|--------------|-------|
| `image/*` (not gif) | `sendPhoto` | Telegram compresses photos; use `sendDocument` for lossless |
| `image/gif` | `sendAnimation` | Telegram auto-plays GIFs |
| `video/*` | `sendVideo` | |
| `audio/mpeg`, `audio/mp4` | `sendAudio` | Shows in music player |
| `audio/ogg` | `sendVoice` | Shows as voice message |
| Everything else | `sendDocument` | Generic file upload |

**Implementation:**

```typescript
async sendFile(jid: string, file: HostFileAttachment, caption?: string): Promise<void> {
  const chatId = jid.replace(/^tg:/, '');
  const source = new InputFile(fs.createReadStream(file.hostPath), file.name);

  if (file.mimeType.startsWith('image/') && file.mimeType !== 'image/gif') {
    await this.bot.api.sendPhoto(chatId, source, { caption });
  } else if (file.mimeType === 'image/gif') {
    await this.bot.api.sendAnimation(chatId, source, { caption });
  } else if (file.mimeType.startsWith('video/')) {
    await this.bot.api.sendVideo(chatId, source, { caption });
  } else if (file.mimeType === 'audio/ogg') {
    await this.bot.api.sendVoice(chatId, source, { caption });
  } else if (file.mimeType.startsWith('audio/')) {
    await this.bot.api.sendAudio(chatId, source, { caption });
  } else {
    await this.bot.api.sendDocument(chatId, source, { caption });
  }
}
```

**Limits:**
- Photos: 10 MB
- Documents: 50 MB
- Video: 50 MB
- Audio: 50 MB

**Auth:** Uses existing `this.bot` (Grammy Bot instance, already authenticated via `TELEGRAM_BOT_TOKEN`).

### 5.2 WhatsApp (`channels/whatsapp.ts` — skill-based)

**API:** Baileys `sendMessage()` with media content types.

**Implementation:**

```typescript
async sendFile(jid: string, file: HostFileAttachment, caption?: string): Promise<void> {
  const buffer = fs.readFileSync(file.hostPath);
  let content: AnyMessageContent;

  if (file.mimeType.startsWith('image/')) {
    content = { image: buffer, caption, mimetype: file.mimeType };
  } else if (file.mimeType.startsWith('video/')) {
    content = { video: buffer, caption, mimetype: file.mimeType };
  } else if (file.mimeType.startsWith('audio/')) {
    content = { audio: buffer, mimetype: file.mimeType, ptt: file.mimeType === 'audio/ogg' };
  } else {
    content = { document: buffer, mimetype: file.mimeType, fileName: file.name, caption };
  }

  await this.socket.sendMessage(jid, content);
}
```

**Limits:**
- All media: 64 MB (WhatsApp Business API); 16 MB (WhatsApp Web/Baileys practical limit)
- Supported types: images, video, audio, documents (PDF, DOC, etc.)

**Auth:** Uses existing Baileys socket (already authenticated via QR/pairing code stored in `store/auth/creds.json`).

### 5.3 Discord (`channels/discord.ts` — skill-based)

**API:** Discord.js `channel.send()` with `AttachmentBuilder`.

**Implementation:**

```typescript
async sendFile(jid: string, file: HostFileAttachment, caption?: string): Promise<void> {
  const channelId = jid.replace(/^dc:/, '');
  const channel = await this.client.channels.fetch(channelId);
  if (!channel?.isTextBased()) throw new Error(`Channel ${channelId} is not text-based`);

  const attachment = new AttachmentBuilder(file.hostPath, { name: file.name });
  await channel.send({
    content: caption || undefined,
    files: [attachment],
  });
}
```

**Limits:**
- 25 MB (non-Nitro servers)
- 50 MB (Nitro Level 2 boost)
- 100 MB (Nitro subscriber)

**Auth:** Uses existing Discord.js `Client` (authenticated via `DISCORD_BOT_TOKEN`).

### 5.4 Slack (`channels/slack.ts` — skill-based)

**API:** Slack Web API `files.uploadV2()`.

**Implementation:**

```typescript
async sendFile(jid: string, file: HostFileAttachment, caption?: string): Promise<void> {
  const channelId = jid.replace(/^sl:/, '');

  await this.client.files.uploadV2({
    channel_id: channelId,
    file: fs.createReadStream(file.hostPath),
    filename: file.name,
    initial_comment: caption || undefined,
  });
}
```

**Limits:**
- Free plan: 1 GB total storage (no per-file limit documented, but practically ~1 GB)
- Paid plans: No per-file limit (subject to workspace storage quota)
- Note: `files.upload` is deprecated; use `files.uploadV2`

**Auth:** Uses existing Slack `WebClient` (authenticated via `SLACK_BOT_TOKEN`).

## 6. Error Handling

### Agent-side errors (MCP tool validation)

These are returned as `isError: true` MCP responses so the agent can retry or adjust:

| Error | Response |
|-------|----------|
| File not found | `File not found: /workspace/group/output/missing.pdf` |
| Path outside `/workspace/` | `File must be under /workspace/` |
| File too large (> 50 MB) | `File too large: 52.3MB (max 50MB)` |
| `fileName`/`mimeType` without `filePath` | `fileName requires filePath` |

### Host-side errors (IPC watcher)

These are logged but don't propagate back to the agent (fire-and-forget IPC):

| Error | Behavior |
|-------|----------|
| Resolved host path doesn't exist | Log error, move IPC file to `errors/`, send text portion if present |
| Path traversal detected | Log security warning, move to `errors/`, discard entire message |
| Channel doesn't support `sendFile` | Log warning, send text portion only |
| Platform API rejects file (too large, unsupported type) | Log error, send text with `[File could not be sent: {name}]` appended |

### Per-channel unsupported types

All four channels support the common types (images, video, audio, documents). No MIME type filtering is needed at the MCP tool level — the platform APIs handle unsupported types gracefully (Telegram/Discord/Slack fall back to document/attachment mode).

## 9. Security Considerations

- **Path confinement:** Agent can only reference files under `/workspace/`. The IPC watcher further validates the resolved host path falls within the group's directory — no `../` traversal.
- **File size cap:** 50 MB hard limit at the MCP tool level prevents agents from sending excessively large files. Individual channels may impose lower limits.
- **No URL-based sending:** Files must exist on the container filesystem. Agents cannot pass arbitrary URLs to avoid SSRF risks.
- **Authorization:** Same IPC authorization as text messages — non-main groups can only send to their own chatJid.

## 10. Open Questions

1. **Should `sendFile` be a separate MCP tool or a parameter on `send_message`?** This design adds it as params on `send_message` for simplicity — one tool for all outbound communication. A separate `send_file` tool would be clearer but adds API surface. **Recommendation: params on `send_message`** (agents already know this tool).

2. **Should we support sending multiple files in one message?** Not in v1. Agents can call `send_message` multiple times. Some platforms (Discord, Slack) support multi-file, but others (Telegram, WhatsApp) don't natively.

3. **Should large images be sent as documents to preserve quality?** Telegram compresses photos via `sendPhoto`. Add an optional `sendAsDocument: boolean` param later if users request lossless image sending. Not in v1.
